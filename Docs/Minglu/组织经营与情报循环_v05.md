# v0.5 组织经营与情报循环

本轮实现原案缺口中的第一组可玩规则：招募、精神、身份维持、长期潜伏与情报递送。为了适配现有八夜切片，采用三夜潜伏和三名候选人的缩小范围；不把这一版称为完整原案系统。

## 如何试玩

开始新局后点击「组织事务」。左侧选择行动人，中间选择接头区域。

1. 接引候选人：占用该成员当夜行动、1AP并预留12银两。封缄后新人加入，接引者成为上线，下夜才可行动。初始容量6人；被捕与潜伏成员也占容量，永久失联不占；本版总名录仍最多8人。
2. 安排另一人潜伏：1AP进入指定区域，需要体力≥50、精神≥40、可疑度<60。进入当夜不产出，后续每2个潜伏夜产出一份情报，第3个潜伏夜后归队。若剩余回合不足首次产出，禁止派遣。
3. 查看缓存情报：潜伏情报暂不增加顶部可用情报。每份标注地区、种类、价值和失效夜。
4. 派另一个人到同一区域递送：1AP，将该区有效缓存全部转换为可用情报；递送者暴露+10。新产出的情报下一夜才能递送，截止夜仍可递送。
5. 可在潜伏期间安排1AP接应，结算时撤回；可以撤销接应预留。潜伏者不能同时做普通任务，归队当夜也不额外行动。

招募和组织行动都能在封缄前通过右侧「撤回」取消。界面滚轮可查看候选人下方的成员身份、精神和缓存清单。

## 精神与身份规则

- 初始精神100。普通外勤/组织行动消耗8；潜伏每夜消耗6；休整恢复18。
- 精神低于30减少1枚基础行动骰，低于15只能休整；潜伏中降到该阈值则撤回。未加入伤病、完整崩溃事件或精神治疗系统。
- 可疑度与暴露分开保存。身份维持默认开启，每夜每位普通可行动成员花2银两、可疑度降低6。
- 关闭维持或资金不够：可疑度+12。达到60后每夜盘查导致暴露+10；达到100使身份彻底暴露并在搜捕阶段被捕。
- 潜伏人员无法维持日常身份，每夜可疑度+4、体力-5、暴露+8。达到抓捕阈值则被捕，其本人所有未递送情报失效。
- 当夜新招募成员不扣维护费、不执行行动。默认每夜结束收入6银两；先招募、再按名录顺序支付维护费、最后领取收入。资金不足时不会负债，未支付成员按未维持处理。
- 审讯泄密也会影响正在潜伏的直接下线。潜伏者被识破后本夜不立即增加审讯回合。

当前身份维持消耗银两，不收原案的0.5AP维护税。这是适配全组织每夜3AP的明确简化，尚未实现职业差异、身份降级、伪造身份和经营产业。

## 情报范围

北衙/东营产出军事情报，其余地区产出治安情报；两类当前都转换为3份通用情报，尚未有类别专属用途。缓存保存在区域接头点，3夜后到期，产出者被捕会销毁本人未送出的缓存。

这里还不是完整的据点设施或逐级单线传输网络：暂未包含据点建造、截获、多人接力、情报品质和眼线产出。

## 配置入口

Unity菜单：`Minglu / 组织规则配置`，支持数值修改、校验、JSON导入预览和导出。

运行配置：`Assets/Minglu/Resources/Minglu/Config/organization_config.json`。

| 字段 | 用途 |
|---|---|
| startingMoney / income | 初始银两 / 每夜收入 |
| maintenance / neglectSuspicion / maintainReduction | 身份维护费用 / 未维护可疑度增长 / 维护下降 |
| recruitCost / capacity | 招募费用 / 活成员容量 |
| restSpirit / actionSpirit / spySpirit | 休整恢复 / 外勤消耗 / 潜伏消耗 |
| spyDuration / spyInterval | 潜伏总夜数 / 产出间隔 |
| intelLifetime / packetValue | 缓存有效夜数 / 递送价值 |

修改后新开局生效；存档保留本局组织规则快照。原有Excel与七张基础配置表继续使用，本次组织规则尚未并入Excel。身份阈值、潜伏暴露增长与候选人姓名等仍为代码规则。

## 存档与资产

新局使用 `minglu-run-v5.json`，v4文件保留且不自动迁移。继续沿用独立局外档案。动态招募角色的姓名、属性、档案、头像引用、上线以及潜伏和情报状态均进入当局快照。

新人复用现有肖像图集，没有为新角色制作专属立绘。候选人三名，属性由种子生成，尚无眼线、精英概率和多渠道招募。

## 验证

规则构建日志：`Logs/MingluOrganizationBuild.log`。共129项检查（原核心23、城市24、派遣30、生命周期15、新组织37）、1000局模拟以及270组初始化组合。新组织固定策略200局中184局胜利，不能作为真人胜率或平衡完成证据。

新增检查覆盖：资金/AP预留、重复招募、容量、撤回、到场时序、精神恢复/限制、维护不足、身份崩塌、潜伏占用、产出时间、异地/重复递送、截止日递送、过期、潜伏暴露失去缓存、接应、扩充名录存读档及随机续算一致。

UI测试将招募、潜伏、维护开关、接应开关、情报产出、递送、扩员后的存读档与原有任务流程串联。截图与最终UI日志见本轮交付文件。
