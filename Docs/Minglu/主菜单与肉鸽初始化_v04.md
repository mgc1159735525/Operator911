# v0.4 主菜单与每局初始化

## 游戏循环

启动进入主菜单 → 新局配置或继续 → 八夜行动 → 成功/失败结算 → 战绩记录 → 返回主菜单或重新配置下一局。

主菜单包含继续行动、开始新局、行动档案、设置、玩法与操作、退出。无存档时禁用继续；存档损坏时显示原因；已结束存档只能查看结局。暂停菜单提供设置、指南、保存返回和保存退出。新局替换现有存档需要在游戏内确认，取消不会初始化新局。

## 局内与局外

局内重置：夜数、目标进度、情报、敌方压力、人员状态、任务指令、体力、暴露、连续出勤、被捕/审讯、已完成/逾期/核实任务、剧情事件、日志、随机数状态。

局外保留：界面音效开关、音量、全屏/窗口选择和已结束局的战绩。没有永久属性升级或继承局内资源。中途放弃的局不计入结算战绩。

## 初始化选项

| 选项 | 行为 |
|---|---|
| 初探 / 标准 / 险境 | 原目标减4 / 不变 / 加8；初始压力减5 / 不变 / 加5 |
| 均衡联络 | 使用基础配置 |
| 情报先行 | 初始情报+2，可行动成员初始暴露10 |
| 隐蔽入城 | 初始压力-8，可行动成员体力85 |
| 危机开局 | 可选，首位成员被捕；默认关闭 |
| 种子 | 1—4294967295，留空随机；独立生成各区-3至+3的暴露修正，限制在0—30 |

每局先复制已导入配置，再应用开局修正，不修改Excel或运行配置源文件。地图使用本局真实修正说明。相同种子、难度、方案、危机选项、配置及操作序列可复现规则结果；每次尝试仍有独立runId，用于战绩去重。世界生成使用独立随机流，浏览菜单不会消耗行动随机数。

目前随机化限于区域风险和行动骰，不是程序生成地图或完整随机事件池。开局方案与难度规则当前在RunLifecycle.cs中，尚未扩展为配置表。

## 存档

- 当前局：Unity persistentDataPath 下 `minglu-run-v4.json`。
- 局外档案：同目录 `minglu-profile-v1.json`。
- 新局、结算、剧情选择、返回主菜单、退出时写入当前局，使用临时文件替换并保留`.bak`。
- 旧v3文件继续保留，新主菜单不自动迁移旧局。
- 结局按runId去重，反复查看结局不会重复登记；再次玩同一种子是新的尝试。
- 保留F5/F9便于当前试玩，并非禁止读档回退的严格铁人模式。强制结束进程或断电可能丢失最后一次自动存档之后的操作。

## 验证

新增15项生命周期检查与270组种子/难度/方案初始化组合；验证源配置不变、开局清空、开局方案、随机复现、独立局ID、档案去重、设置存读档、当局存读档与续算一致。

UI自动测试从真正主菜单开始，覆盖设置保存、指南、新局种子、危机选项、返回与继续、替换存档确认、旧有任务派遣完整流程、失败结算、战绩查看与再次查看结局不重复登记。

构建与测试日志：`Logs/MingluLifecycleFinalBuild.log`、`Logs/MingluLifecyclePlayer.log`、`Logs/MingluLifecycleFinalPlayer.log`。这是可玩框架版本，尚未制作长期解锁树、遗物/构筑系统、分支章节、音乐和完整教程关。
