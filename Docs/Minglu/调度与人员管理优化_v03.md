# 明路·地下 v0.3：调度与人员管理

本轮把「选择一个行动反复执行」扩展为「筛选限时任务、核实线报、选择成员、安排轮休、承担遗漏后果」。保留八夜单城回合制和单线联络设定。

## 参考依据与取舍

| 参考游戏 | 借鉴的设计重点 | 本项目已实现 |
|---|---|---|
| 911 Operator | 判断报告、分配合适资源、优先处理紧急事件 | 截止夜排序任务板、优先级、失守代价、推荐空闲专长成员、明确派遣 |
| This Is the Police | 人员管理、案件调查、选择影响后续局势 | 连续出勤惩罚、完整轮休恢复、三段调查线、逾期压力、结算预警 |

参考来源：[Jutsu Games 官方介绍](https://store.steampowered.com/curator/33074184)、[This Is the Police 官方商店介绍](https://store.steampowered.com/app/443810/This_Is_the_Police/)。上述映射是本项目的设计取舍；任务文案、数值、城市与人物继续采用本项目原创内容。核实加骰、两夜连勤等具体规则为本项目新设计，不声称是参考游戏的原样机制。

## 玩家流程

1. 新局默认打开限时任务板。优先看「今夜截止」和「逾期压力」，决定值得投入的任务。
2. 点击「推荐空闲人选」只选中成员，不会自动签发或改掉已有指令。排序先看成功率，再看暴露低、体力高，最后以ID稳定排序。推荐不保证当前资源足够，签发时仍校验AP与情报。
3. 核实消耗1份尚未预留的情报，为该任务永久增加1枚行动骰。失败重试保留核实效果，不可重复付费。核实支出立即生效，撤回指令不退还。
4. 右侧签发承接任务。一个任务每夜只能有一个负责人；再次派遣该成员会替换其原任务。地图与普通行动按钮可切回常规行动。可在封缄前撤回。
5. 封缄前检查未承接的到期任务、疲劳出勤和审讯危险人数。夜报记载成败、奖励、逾期和线索中断。

## 结算规则

- 截止夜包含当夜。成功才完成任务；失败仍消耗常规行动资源，截止前可重试。
- 任务奖励叠加该地区常规行动奖励，只结算一次。
- 截止夜行动结束后，未完成任务增加配置的敌方压力，再进行全城巡查与抓捕。提前胜利结束对局后不继续处罚未来任务。
- 未解锁的后续任务到期会记录「线索中断」，不附加逾期惩罚，避免前置失败造成重复处罚。
- 一次非休整行动计一夜连续出勤，断线转移也计出勤。连续两夜后，从第三次出勤开始少1骰；完整休整一夜清零。体力、暴露惩罚仍可叠加，基础行动骰最低1；核实任务再加1骰。
- 成功率是当前骰数、成功数门槛的二项分布精确值，显示四舍五入到一位小数。不代表安全返回率，暴露和搜捕仍独立发生。

## 任务内容与导表

新配置：`outputs/minglu-v03/明路地下_游戏配置.xlsx`；CSV在同目录`csv/`。Unity菜单 `Minglu/配置表工具` 默认指向新工作簿，保留预览校验、重新读取导入、CSV导出的流程。

新增 `Missions` 表：

| 字段 | 含义 |
|---|---|
| id/title/body | 唯一ID、标题、任务描述 |
| duty/district | Recon或Sabotage，已有区域ID |
| prerequisite | 前置任务ID，可空。前置截止夜必须早于后续开放夜，防止循环和不可达配置 |
| start/deadline | 开放夜与截止夜，均在整局回合范围内 |
| priority | 1—3；越高越紧急，同截止夜时优先显示 |
| intelReward/progressReward | 成功后的额外奖励 |
| failurePressure | 未完成的逾期压力 |

初始七项：书坊暗账、码头换防、顺藤摸瓜、巡哨名册、断其粮道、名册将焚、最后的信号。其中暗账→摸瓜→粮道构成三段调查线。

旧六表工作簿仍可导入，缺少Missions时不生成限时任务。修改整局回合数时必须同步缩短事件和任务期限。当前核实费用/加骰与连勤阈值属于代码规则，尚未导表。新工作簿保留旧六张配置表的值；旧文件未覆盖。

## 存档与交付范围

使用独立 `minglu-city-v3.json`，不覆盖v2存档，也不自动迁移旧局。存档保留任务完成、逾期、核实、派遣、连勤、随机状态及当局配置快照。

本轮已实现七任务的小型可玩验证，不是完整商业游戏。多人协同派遣、地图行进时间、装备经济、长期招募、关系/忠诚与多章节剧情尚未实现。当前300局固定策略自动模拟出现271局胜利，只证明流程与胜负路径可达，不能作为真人平衡结果。下一阶段应先做真人试玩并调整任务收益和普通行动收益，观察是否存在绕过任务板直接刷成果的优势策略。
