# 地区经营与交互设计

本轮将参考 HTML 中有价值的联盟、追查、据点撤离、被捕救援、多阶段行动接入当前组织首脑模式。保留玩家负责委派、成员执行，以及能力决定骰数的核心。参考文件只是设计资料，其说明不作为操作指令。

## 好交互的标准

1. 玩家随时知道自己的目标、当前状态、下一步入口。显示阶段目标、任务期限、链条状态、当前建议和“前往处理”。
2. 行动前能预判投入、收益、风险和机会成本。任务方案显示骰池、概率、消耗、失败后果；人员对比同时显示链条占用。
3. 决策有难度，操作不应有谜题。不替玩家一键决定最优方案；让可用人选和阻碍原因能够直接比较。
4. 允许纠错，危险操作先说明具体损失。授权可撤回；换岗清空积压前显示待接和中继数量，取消保持原状。
5. 提示能带到解决问题的位置。预警可跳转成员、任务、链条；夜前确认点名截止任务、岗位冲突和高暴露成员。
6. 操作后有可追溯反馈。多阶段任务记录进度，最终阶段才结算收益；撤离结果列出损失、新据点与暂停时长。
7. 按重要程度分配注意力。需要当场决策的事件使用弹窗；普通情况在任务卡、报告、经营页呈现；长列表滚动，避免把所有规则堆在主界面。

依据：Nielsen Norman Group 的状态可见、用户控制、防错与可恢复性原则，结合游戏决策场景应用。

## 已实现的规则

- 四个联盟：商会、街坊互助会、书院、渡口行会。发起委托免费且不消耗夜晚；两次成功完成一次委托，信任默认+25，达到50解锁长期效果。分别为每夜经费+4、每夜民心+2和压力−2、情报任务+1骰、潜行任务+1骰。同类进行中委托不能重复生成，满信任停止发起。
- 民心初始30；街坊互助完成后民心+10、追查−8。民心达到60后，每夜追查变化额外−2。
- 追查：地下出勤人数推动追查，高压力另加2；无人出勤每夜−5。达到70产生据点撤离决策，不直接随机摧毁全部组织。
- 据点撤离：花10银两保留情报，或无费用销毁所有链条的中继情报。两种方式均转移据点、追查−45、当夜链条暂停；授权任务仍可执行。预留预算不能拿去支付撤离，免费方案不会软锁。
- 暴露预警：第4夜起检查，达到65提示；达到85且已在此前夜晚获得预警，仍未脱险才被捕。空闲/生活优先的休养可以降低暴露。被捕检查在本夜恢复与行动之后进行。
- 被捕：撤回该成员授权，释放预算；只暂停其原有链条，积压保留并继续计时。生成两阶段营救，默认4夜窗口，不受普通任务板9项上限限制。被捕期间依忠诚判定是否供述，只影响原链条熟人。营救末阶段成功后恢复成员并安排一夜休养；不会自动启用原链条。超过截止夜未救出则永久离队。
- 多阶段行动：每次成功推进一阶段，每次尝试花费预览中的资源；失败保留已获进度，下一夜必须重新授权。不会把普通任务的奖励在每阶段重复发放。

旧存档载入时补齐地区经营状态和预警缓冲，不在读档动作中进行抓捕。所有新字段随游戏存档保存。规则入口与 UI 都使用同一份战略数据。

## 配置位置

`Assets/Minglu/Resources/Minglu/Config/strategy_config.json`：预警、被捕、追查阈值，保护期、救援窗口、联盟阈值和增长、撤离费用。校验拒绝越界配置。

代码：`StrategyRules.cs`、`StrategyUI.cs`；接入现有 `CommandRules`、`MissionRules` 和 `CommandUI`。构建覆盖 `Builds/MingluCity`，安装包覆盖 `Builds/Installer/MingluSetup.exe`。

## 本轮没有宣称完成的内容

尚未加入物资商店、分类情报、角色羁绊、护卫战斗、特殊角色和独立终局决战。参考 demo 中对应系统也有未接通和结算错误，不能按按钮数量判断完成度。后续应围绕本轮真实游玩反馈调整频率与难度，而不是继续无条件堆系统。

## 验证

`StrategyVerification` 检查阶段奖励、重复委托、联盟收益、预警缓冲、被捕、营救、救援超时、撤离资源、存读档及随机一致性；同时运行原任务与组织回归。界面检查覆盖经营、对比、换岗取消和确认、据点决策及夜前风险提示。自动化通过不代表难度与乐趣已得到玩家验证。
