# 机构任职与情报来源

## 生效规则

适用于当前组织首脑模式。玩家安排人事与任务，成员自行执行。

- 职业与任职机构分开保存。民间书吏、账房、药师等并不自动拥有敌方情报。
- 具体敌方机构：政务署、税务署、巡防局、驻军司令部。分别描述行政人事、征收物资、巡防拘押、军需调令来源；当前送达后统一计为可用情报，尚未细分四种库存或任务匹配奖励。
- 新局首名成员保证拥有一个随机敌方机构职位；其姓名、性别、外观、职业和能力仍随机。其他开局或招募成员有25%概率已在敌方机构任职。开局可用情报为0。
- 只有具备任职身份的成员可选作链条内线。接头人与交通员无需敌方身份。规则层再次校验，不能只靠绕过界面获得情报。
- 启用完整链条后，内线隔夜按情报能力判定产生待接情报；接头与外送各跨一夜。只有外送成功才增加库存及送达计数，任务优先、休养和失败仍会延迟链条。
- 普通任务、生活、主动发现不会奖励可用情报。主动发现仍可产生待授权任务；机构内线成功观察仍可提出任务建议。

## 扩展内线

人事档案 → 选择尚无任职身份的成员 → 建立机构任职 → 选择机构 → 任务簿签发给本人。

选择机构只生成任务，不立即取得身份、不花钱、不自动授权。本人按说服能力投骰，需2个成功；常规方案无额外资金或情报需求，失败可在期限内重试。成功只取得机构内线资格，随后弹窗引导配置联络网，不直接奖励情报。

同一人不能同时申请多份任职任务，已有机构职位不能直接切换。少于四夜时不开放新申请，避免承诺无法完成的首次传递窗口。四夜只是理论最短窗口，周期、失败和占用仍会造成延期。

## 旧存档与配置

增加 `CommandPerson.institution`，0代表民间，1—4对应机构；任职任务使用 `operation=4`、`target=申请人`、`institution=目标机构`。`institutionRevision`使迁移只执行一次。

没有机构资格的旧链暂停，待接与中继积压清空；已送达库存、累计送达及战绩保留，不消耗随机数。更新提示给出恢复路径：建立任职身份，再重新启用链条。不会凭空把旧民间角色改成敌方雇员。

组织模式任务模板中的旧 `intelReward` 字段为兼容保留，但必须为0；配置编辑器拒绝非零值，任务创建、结算与收益展示也不能用此字段绕过链条。历史原型模式的其他配置不属于本次改动。

## 验证入口

- `Minglu.EditorTools.InstitutionVerification.BatchDeliver`：机构规则、旧存档迁移、逐环传递、任职任务保存/读取、原有任务与经营回归、60种子完整运行，随后构建固定游戏目录。
- 构建游戏参数 `--minglu-capture <输出路径> --institution-only`：真实按钮流程检查候选资格、取消、任职任务签发、保存读取、结算后新内线准入，使用隔离存档。
- 安装脚本现在默认调用包含机构规则的验证入口，继续覆盖原安装包路径。
