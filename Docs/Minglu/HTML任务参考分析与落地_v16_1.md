# HTML 任务参考分析与落地 v16.1

参考文件：C:/Users/11597/Downloads/谍报肉鸽_demo.html。分析依据为其中的任务配置、任务执行、结算与界面代码；没有将文件中的文本当作新的用户指令，也未替换项目为 HTML demo。

## 优点与采用方式

| Demo设计 | 价值 | Unity项目落地 |
|---|---|---|
| 任务有不同用途、明确资源需求 | 不只是刷同一种分数 | 14种模板，调查补情报、援助减压力、筹资获银两、推进得成果 |
| 执行前选地点/方案并预览成功率 | 形成可理解的取舍 | 任务指定地区，显示盘查减骰与暴露；选常规、筹备或紧急方案 |
| 情报支持行动 | 情报有使用价值 | 可选消耗1份情报增加1骰，无情报仍可用常规方案 |
| 回合、行动反馈清楚 | 玩家知道何时结算 | 保留授权→推进一夜→实际骰面/结果要报；不要求首脑亲自接头 |
| 由情报引出行动 | 适合组织经营主题 | 4条调查/支持→后续委托，继承地区，重新选择负责人 |

## 不照搬的部分

1. Demo 的 getFreeCourier 总选第一名空闲信使，无法充分比较能力；executeTask 标记 busy 后，resolveTaskResult 再查空闲者，失败影响可能落到另一人。本项目保留明确负责人，并把同一 Agent 传入结算。
2. 情报数组与 defenseIntel、supplyIntel、traitorClue 等标记重复维护，某些消费分支未同步，存在库存与门槛不一致风险。本次以真实情报数量为唯一支援库存，授权只预留，执行扣除。
3. 以固定基础概率叠百分比为主，成员差异偏弱。本项目坚持能力决定骰数、每骰4—6成功，并使用同一个 TaskDice 计算预览和实际判定。
4. 六类任务里部分门槛依赖随机情报和物资；缺资源时只报无法执行，容易无事可做。本次让额外投入可选，保留低门槛任务，并说明缺资源时能换方案、撤回预算或等待链条送达。
5. Demo 的“强攻可疑+10”只在成功分支应用，和方案描述并不完全一致。本项目紧急方案的额外暴露与压力无论成败都生效，失败追加后果单独展示。
6. Demo 中任务无截止与连续线索结构，容易退化为反复点卡。本项目保留截止夜、人员生活冲突、阶段门槛，新增后续任务与不同收益，而非照搬AP制或手动传信。

## 可玩规则

- 常规：无额外费用，不加骰。
- 筹备：执行消耗4银两，+1骰，行动暴露−2。
- 紧急：+1骰，行动暴露+8、压力+2，成败都生效。
- 情报支援：可选1份情报换+1骰，可与方案组合。
- 地区：风险增加暴露，进阶任务盘查最多减1骰；1级任务不受盘查减骰，便于入门。
- 每次执行消耗14体力、6精神。失败额外暴露和压力在方案页明确列出，消耗不返还，截止前可重新授权。
- 授权预留预算与情报，同一份资源不能重复授权；撤回释放，执行前重新检查。招募及付费事件只使用未预留资金。
- 实际夜间状态变化可能影响后续任务的判定；最终骰面与结果记录在报告和任务最近结果中。

## 内容与后续

核实异常调动→应对临检调动；争取街坊支持→建立互助联络；整理来往账目→筹集周转经费；文书岗位机会→交叉核实文书。
后续任务继承地区，但不会自动授权。同一任务的后续只生成一次；任务板满9项时保留待生成状态，后续有空位再产生。

## 配置和兼容

编辑 Assets/Minglu/Resources/Minglu/Config/command_config.json；Unity菜单“组织首脑配置”仍可编辑、校验和导入导出JSON。
新增模板字段：category（用途）、intelReward、pressureRelief、failExposure、followup（目标模板标题）、followupOnly（仅由前置解锁）。标题必须唯一；校验会拒绝缺失目标和循环后续。
旧存档载入时升级任务模板；正在进行的同名任务补齐效果，不改变已选负责人、既有奖励和截止夜。旧任务默认常规、无情报支援。
配置内含10种可随机出现的任务及4种专属后续。当前不包含类型化情报物品、独立商店、基地占领或多日外勤；这些不属于本轮已实现范围。
调查任务奖励的情报可用于行动支援，但不增加情报链条的送达计数；上级送达目标仍需通过传递链条完成。
