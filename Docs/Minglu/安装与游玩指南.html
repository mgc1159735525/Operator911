明路·地下

你是地区负责人。你决定目标、安排人员并建立联络网；成员负责具体行动。你的工作是让组织能持续完成任务，同时保住人的生活与信任。

安装与更新

  1. 关闭旧游戏，双击 MingluSetup.exe，选择“下一步 → 安装”。
  2. 有 D 盘时默认安装到 D:\Games\MingluCity，没有 D 盘时使用当前用户的 Programs 目录；覆盖更新沿用已有位置。安装后从桌面“明路·地下”打开。
  3. 以后更新同一目录。保留 EXE 同目录的数据文件与运行库，完整目录才可运行。

日常运行：D:\Games\MingluCity\MingluCity.exe
固定安装包：D:\UnityProjects\Operator911\Builds\Installer\MingluSetup.exe
游戏窗口名为“明路·地下”，版本号显示在主菜单左下。

先看目标，再点需要的详情

常用按钮用图标加短标签表示；不必记住图标含义，先按旁边的文字操作。中央仍是城区地图。

  1. 看下一步：地图底部“当前重点”告诉你现在优先处理什么，右侧按钮直接前往。下方反馈只显示摘要，点“详情”看完整指示与刚才的操作结果。
  2. 看资源：点击顶部“可用情报”或“可用经费”，查看可用数、已预留数与扣除规则；“成果”“追查 / 阈值”“民心”也能点开解释。
  3. 做决定：从任务簿点“安排任务”或“推荐人选”。签发页直接保留门槛、期限、成功率、消耗与失败风险；“任务背景”读全文，“后果详情”看生活、联络与成长影响。
  4. 按需学规则：联络网点“传递规则”；人事档案点“个人档案”，再用“成长规则”“生活与近况”查看说明和成员经历。切换“生活优先”会撤回任务，先看选项下的提示。
  5. 看结果：值夜报告先看“结果摘要”；想知道骰面和过程，再切到“完整判定”。“报告说明”解释读法，“要报留档”回看重要事件。

说明弹窗的“返回”或 Esc 回到刚才的页面；查看说明不会扣钱、掷骰或推进夜晚。真正推进前仍需在“今夜安排”确认。灰色按钮旁的原因、红色期限和风险提示要优先处理。

第一次玩：先试八夜新手演练

主菜单选择“新手演练”，再点击“开始新手演练”。已有进度时选“继续教学”接着练，也可选“重新演练”；结束后可选“再练一局”。演练独立于正式行动，退出、继续或重玩不会替换正式局，也不计入正式战绩。

  1. 先认识人：打开成员档案，查看能力、表身份与状态。你负责安排人手，成员执行具体行动。
  2. 比较后再签发：打开教学任务，比较候选人的骰数和成功率，选定负责人后签发。前面的课跟随高亮操作；当前阶段尚未完成时，无关按钮会暂时锁定，完成提示中的操作后再进入下一课。
  3. 看一次真实结果：确认今夜安排并推进，打开报告中的完整判定，查看骰面、成功数、投入和结果。演练也会失败，失败不代表点错按钮；按报告说明，在期限内重新安排即可。
  4. 建立传递链：安排在敌方机构任职的内线、接头人和交通员，三人不能重复。产出、接头、外送逐夜推进；普通任务不能凭空替你补上机构情报。
  5. 让成员有生活：按提示安排生活优先，留意地下岗位会等待。之后提示逐渐放宽，你自己决定谁做任务、谁保住链条、谁恢复状态。
  6. 完成一次自主安排：争取在八夜内完成两项任务、送达一份机构报告并处理一次事件。第八夜回顾会列出实际做到的内容；未达标可以重玩，熟悉后再开始正式行动。

随时暂停和复习：按 Esc 可暂停教学；从暂停页选择“保存教学，返回主菜单”，下次在“新手演练”中点击“继续教学”。有尚未应用的外观修改时，先处理草稿确认。点击“回看说明”或“回看教学”可翻阅已经学过的课程，回看不会推进夜晚，也不会重做已经执行的行动。教学进度单独保存在 minglu-tutorial-v1.json，正式行动仍用 minglu-run-v14.json。

正式行动：先学会一次有用的安排

  1. 新局：首次没有已完成战绩时默认“初探”，你仍可修改。建议用二十夜剧情了解完整循环。普通八夜行动是时间更紧的短局挑战；主菜单“新手演练”才是独立的八夜教学。
  2. 第一夜：跟随地图底部“当前重点”打开一项任务。先看目的和期限，比较负责人，查看成功率与代价，再签发。返回地图并确认“结束今夜”，看成员提交的结果。
  3. 第二夜：从“联络网”选择机构内线、接头人和交通员，三名成员不能重复，然后启用。缺少内线时，从“人事档案 → 个人档案”建立敌方机构任职任务。
  4. 理解时间：产出、接头、外送至少跨三次结算；每环判定可能延后。查看、比较与调整都不推进夜晚，结束今夜才执行。任务占用成员时，该成员的联络岗位可能等待。
  5. 明确下一目标：地图左下“主线委任”说明本局危机与当前章节。选择一种处理方法，签发给合适的人，同时查看组织还缺的送达、成果与身份条件。

不必派满所有人，也不必接完所有机会。空闲成员会恢复状态、处理日常并积累表身份经验；为明夜保留人手也是有效安排。

今夜安排：少翻档案，再确认推进

地图左下的“今夜安排”与“结束今夜”进入同一张核对表。只在最后点击“确认安排 · 推进一夜”时结算，查看核对表不会花费资源。

  • 本夜安排：集中显示已签发的任务阶段和启用联络链的本夜预测。
  • 待续办：已完成一部分、调查完毕或上次未成功但仍有完成窗口的目标。点击“查看任务”即可重新比较和签发，返回后仍在这张核对表。
  • 冲突与风险：查看今夜确有工作的链条岗位被谁占用、期限不足、积压或人员风险。点击可打开任务、联络网或成员档案；调整后返回核对。

失败、阶段完成、调查和因条件变化而撤回的授权会合并进入夜间要报，说明进度、投入与下一步。首项任务失败不会清掉“已学会签发”的进度。内线只在观察周期尝试产出，失败后显示下次观察夜数；接头与外送仍按后续夜晚尝试。

键盘在可选列表中上下切换时，列表会跟随焦点滚动。确认前可以看见正在选择的成员或档案。

二十夜主线：三章委任与组织能力

新局种子会选出“未寄出的名单”“冬粮账簿”“断线之前”之一。每局三章，每章有两种方法。完整胜利需要三章都完成，并达到本局组织门槛；完成故事任务之后，组织仍要有持续送达与维持工作的能力。

方法需要什么取舍
档案核证已送达的指定敌方机构报告；仍需指派成员掷骰执行。通常只需一个成功阶段，节省夜数；取得对应报告本身需要机构任职与传递链。
替代方法不要求指定机构档案或机构任职；任务仍有对应能力与成功数要求。通常需两个成功阶段，耗时更长；部分方法提高民心或减少地区风险。

从“主线委任 → 当前主线”选方法，再在熟悉的任务弹窗中比较与签发。主线不是点一下就立即完成：多阶段任务每次执行后重新授权，可更换负责人，已经成功的阶段会保留。

改选方法：尚未执行时，可以回主线点击“重新选择方法”；已授权则先在任务内撤回负责人。已有执行结果、调查成果或完成阶段时，不能改换方法，需要继续当前路径。取消尚未执行的方法不消耗资源、夜数或行动随机数。

“行动进度”保存已采用的方法与章节后果，“组织概况”列出当前组织门槛。临近截止时先看最少所需夜数；没有机构档案时，可直接用替代方法推进。

此前开始的旧局与八夜短局继续沿用原目标，不会因更新被强加三章任务。要体验新剧情，请开始新的二十夜行动。

机构情报、链条与档案有什么区别

只有在敌方政务、税务、巡防或驻军机构任职的成员能作为内线产出机构报告。民间成员可以接头与外送；普通任务和日常生活不直接生产库存情报。

  1. 报告在途：内线产出后等待接头，再进入中继，最后外送。队列先到先传，正常换岗保留原报告的机构与来源；不会因为换了新内线，就把旧报告改成新机构报告。
  2. 库存情报：成功送达后增加可用情报，可在行动中投入支援。投入支援会消耗库存。
  3. 机构档案：新剧情把送达报告另行留档，记录来源、机构和送达夜数。从“主线委任 → 情报档案”查看。档案可作为核证依据，不重复扣除库存情报，核证后保留记录。

暂停链条仍会让积压报告老化。失陷可能损坏对应环节；换岗弹窗会提示损失。只有完整送达的报告能支持机构核证。

签发前看这五项

信息判断方式
时间“今夜必须开始”按剩余阶段计算。成功率是本阶段一次尝试的概率，失败可能需要额外一夜。
负责人能力决定骰数，每骰 4—6 算一次成功。还要看身份准入、状态、今晚有无链条工作。
方案常规不追加经费；“筹备”每次 4 银两换加骰及较低暴露；“紧急”加骰但提高暴露与压力。情报支援每次使用 1 份库存情报。
调查占用一夜，成功后目标执行加骰并降低暴露；不会完成目标、不产生库存情报。期限紧时要计入这额外一夜。
机会成本一人一夜只做一项地下工作。任务优先于岗位，要看链条等待、连勤、信任和身份成长是否值得。

授权时预留预算，结束今夜才执行并扣除。失败也消耗投入；撤回尚未执行的授权会释放预算。

成员生活、成长与危机

  • 招募前可预览随机候选人的能力、机构身份和生活牵挂，确认后花费 12 银两；反复开关预览不会重抽。在编人数包含被捕待救者，永久离队不再占名额，历史档案仍保留，可接纳替补。每名在岗成员每夜需要 2 银两维护。
  • 地下任务与成功的岗位工作积累能力经验；空闲日常培养表身份。两种成长需要轮换安排。
  • 生活优先会撤回任务，暂停该成员地下工作；原联络岗位等待，可另派替补。正常交接后链条暂停，需要核对后再启用。
  • 暴露、连续工作、信任与地区压力会引发问题。被捕成员可能出现限期救援，追查达到阈值会出现撤离选择。
  • 重要事件先展示后果再选择。结束后的“夜间要报”合并结果；“值夜报告 → 要报留档”保留最近 80 则消息，已读后仍可回看及跳转相关档案。详细骰面在“完整判定”中查看。结局的“回看每夜决定”也能打开要报留档，相关链接只回看当夜报告，不再改变已结束的对局。

界面、保存与损坏恢复

城区地图始终在中央。左侧按钮打开各业务弹窗，右上“设置”集中提供保存、读取、指南、声音与显示、返回菜单及退出。Esc 返回；F5 保存；F9 读取；滚轮翻阅档案。

新局、夜间结算与事件选择后自动保存。存档目录继续使用：

%USERPROFILE%\AppData\LocalLow\DefaultCompany\Operator911

正式对局文件为 minglu-run-v14.json，新手演练为 minglu-tutorial-v1.json，设置、人物预设与正式战绩为 minglu-profile-v1.json。演练保存、读取与重玩只处理教学进度，不替换正式局；正式旧局继续沿用开局时的目标。文件名保留是为了兼容，游戏改名和覆盖更新不移动用户存档。

  • 保存失败会弹出提示，可重试或暂留当前界面；未成功保存时，正常关闭窗口会被拦下。主档有效时正常读取；主档损坏或丢失时尝试上一份有效 .bak 并明确提示，恢复的进度可能较早。
  • 读取备份本身不覆盖原文件。后续保存会保留损坏原件为 .corrupt-*，避免把损坏主档覆盖到好备份上。
  • 两份文件都不可读时，游戏保留原件并报告失败。如果需要排查，先复制整个存档目录留存。
  • 开始新局会提示替换现有对局；仅剩备份时同样提示。覆盖安装和卸载不会主动删除用户存档目录。

新版人物绘卷

整体重建：参考《太阁立志传 5》的绘像风格与清楚的翻选布局，使用新制作的原创人物和部件。头发、脸廓、耳朵与脖子合成完整头部原画；眼、眉、鼻、口换成独立绘制的部件。旧的单独发型和耳形按钮已撤除，不同发型从“头部”中选择。随机成员、负责人和人事档案共用这套新绘卷。

人物绘卷已使用重绘的男女头部与眼、鼻、口。此前已校正眼睛大小、眼鼻间距和鼻部宽度，并调整鼻根与脸部的光影衔接；本轮界面精简不改变这些美术资源。已有的款式和配色选择保留，更新后关闭并重新打开原游戏即可看到调整，无需重新开局。操作方式不变：先选完整头部，再逐一切换眼、眉、鼻、口与胡须；用“查看面容”检查局部，回到整身预览看比例。“对照原貌”可比较编辑前后，确认后再保存。塑造长者时，可同时选择长者眼口和银白须发，让年龄特征一致。

  1. 先选容貌：从主菜单或人事档案打开“人物绘卷”。右侧“选择容貌”可切换性别、完整头部、服装、饰物与配色；男女各有 12 款头部、各 8 款服装。饰物有 3 款，另可选“无”。
  2. 再选部件：进入“选择部件”，眼睛、眉形、鼻形、嘴形每类男女各 8 款；男性胡须有 7 款和“无”，女性不显示胡须。点击款名或右箭头换下一款，左箭头回上一款，首末款循环。每款五官使用独立绘图，替换时不靠拉伸同一部件制造差异。
  3. 查看搭配：左侧显示完整立绘，“查看面容”可放大，“对照原貌”可比较编辑前的样子。撤销、重做和还原都只影响当前预览。先固定头部，再逐一比较部件更容易看出变化。
  4. 随机与收藏：“随机设定”中点击部位，将其设为“保留”或“随机”；也可“全部保留”“全部随机”。随机维持当前性别，保留项不会被改动。进入“收藏预设”选择槽位，保存当前预览或读取到预览；覆盖已有预设会先确认，收藏不会直接替换角色当前外观。
  5. 确认后应用：点击绿色“确定 · 开局外观”或“确定 · 保存外观”应用并保存。“返回”、关闭或 Esc 会先询问是否放弃未应用修改，选择“返回编辑”可保留草稿。保存失败会显示原因，可“重试保存”或返回编辑，当前预览仍保留。外观不影响角色能力。

须发共用配色，长者随机形象优先银白，少数使用灰色；仍可手动修改。“选择容貌”内的“按年龄设色”可恢复年龄推荐色；保留须发色后，随机与换头部仍使用所选颜色。肤色、衣色和背景也可逐款选择。

旧存档与旧预设：载入旧外观时，按原年龄和发型选择接近的新完整头部，保留仍有效的五官、胡须、饰物与配色选择。原画已重做，新旧形象不会逐像素相同；只查看或取消编辑不会把迁移结果写回原文件，确认应用后才保存新的角色外观。无需重新开始对局。

在 Unity 手动调整人物部件

如果想亲自调整眼睛、鼻子、胡须与衣领的配准，用 Unity 打开 D:\UnityProjects\Operator911，等待编译后，选择顶部菜单 Minglu → 美术工具 → 人物部件校准器。这项制作工具在 Unity 编辑器中使用，游玩游戏不需要安装 Unity。

  1. 选择性别、完整头部与部件款式，先使用当前头部 / 当前款式的范围。
  2. 选中部件，调整 X / Y、宽高倍率、旋转；眼睛与眉毛还能单独调整左右间距。数值以 400×600 画布为准，X 正数向右，Y 正数向下。
  3. 查看实际渲染预览，并换相邻头部或款式检查。完整头部包含头发、耳、脸廓，它们一起变动；这些内容尚不能独立拆分调整。
  4. 导出 CSV 留作备份，将确认后的结果保存至项目表 Assets/Minglu/Resources/Minglu/Config/portrait-calibration.csv。
  5. 重新验证构建并覆盖安装到原游戏目录，再启动游戏查看。单纯导出 CSV 或改项目文件不会热更新已安装 EXE；不需要删除旧存档。
