# 行动引导与组织安全 v0.13

本轮接入组织安全的第一阶段，并以明确行动目标为交互重点。运行 `Builds/MingluCity-v13/MingluCity.exe`。完整敌方人物AI、路线拦截和整个人际信息矩阵仍在后续范围内。

## 玩家如何操作

新战役默认进入「今夜指引」。右侧固定显示交通站状态、当前建议、成本、结果、推荐空闲成员与必做主线。点击「安排某人」只签发一项指令，右下角「封缄」才会推进夜晚。

1. 首夜接回密件；接收没有送达奖励。
2. 次夜外送已入站密件，获得列明的成果、情报与银两。
3. 同时通过右侧主线入口安排「古寺落脚」等必做任务。主线到期前一夜会提升为优先提示，避免只送情报却错过胜利条件。
4. 追查偏高时转移交通站；中断时先恢复。没有可执行交通工作时处理主线或休整，不必为了花完AP做无目的行动。

推荐使用真实指令校验，优先空闲、低暴露、体力充足成员；不会覆盖已有工作。普通密件按钮也拒绝覆盖其他指令，需先撤回。禁止接收已经来不及外送的密件；普通派遣界面禁止签发成功率为零的操作，并提示换人、核实或换目标。核实加骰后可以重新判断。

密件卡显示不可操作原因。封缄前列出成员工作、到期任务/密件、主线警告和维护费用；全员未派遣时明确显示「全员休整 · 推进一夜」。在其他页可随时点「今夜指引」返回。

## 安全规则

- 交通站初始位于西市，追查0。每次接收或外送增加8追查。
- 接收或外送过的成员知道当前地址。普通成员不会默认知道地址。
- 审讯首次突破时，如果囚犯知道当前站址，追查增加35；只知道旧址或不知道地址则不增加。原有直接下线暴露规则保留。
- 转移需要1AP、8银两及交通体力/精神成本，暂停同夜其他交通工作。目的地自动选择其他基础风险较低的地区；追查减少45，地址代次更新，旧址知识失效。执行转移者知道新址，已入站密件随站移动。
- 无接收/外送的夜晚追查自然降低2；达到100时不会被自然衰减抵消。
- 追查达到100，站点中断，销毁尚未外送的在站密件；已送达回执、未接收密件与来源保留。下一夜转移可恢复。
- 追查65以上建议转移，但允许玩家自行取舍。追查为0时不允许浪费资源转移。

这套规则是透明的站点追查模型，不是敌方人物在地图上寻路或概率拦截。当前只隔离交通站地址知识，尚未实现所有角色真名、来源和任务知识矩阵。固定规则暂在 `SecurityRules.cs`，未声称已经加入Excel配置工具。

## 存档

沿用现有 `minglu-run-v8.json` 文件位置，新增可序列化站点与地址知识。旧存档缺少安全数据时使用新站点默认值；不回溯推断旧交通员知道地址。建议保留原存档备份，写入机制保留 `.bak`。由于新增指令类型，v0.13保存的进行中转移指令不保证可被旧版本读取。

## 验证入口

`Minglu.EditorTools.SecurityVerification.BatchDeliver`：有效期防误操作、地址知识隔离、转移冲突/消耗/保留密件、旧址失效、搜查损失、恢复、存读档及旧数据默认值；另执行原交通17项检查及50局模拟。

实机 `--minglu-capture <路径> --guidance-only`：开局引导、接回、外送、转移指令存读档、结算恢复与主线导航。测试将追查设置为78以确定性覆盖危险提示，不代表正常第三夜一定达到该值。
