# 自定义外观根因审查

日期：2026-09-27。范围：用户截图、现有运行时代码、着色器、原始图集与旧验证代码。本次是静态与素材审查，没有修改运行时或重新宣称画面修复。

## 结论

问题主要来自素材规范与合成架构。之前将完整写实人脸的局部像素替换作为五官拆分实现，再以固定矩形拼接头发、头部和衣服；这种方法可以产生变化，但不能保证换装与混搭自然。调整预览缩放、头像裁切和随机年龄只能缓解部分表现。

## 已确认的问题

1. 五官不是真正独立资源。`PortraitFeatures.shader` 的 `patch` 在同一张完整脸图集中采样另一列人脸，按椭圆权重覆盖原脸。眼、眉、鼻、嘴、耳朵没有各自的透明部件和独立锚点。替换会带入供体的周围皮肤、皱纹和阴影；混合区可能保留两套轮廓。界面的四选项实际是四个年龄供体，而不是四种经过统一规范设计的鼻型或眼型。
2. 对齐参数是全局常量。着色器仅按性别改变眼眉高度，其余位置固定；没有每张基础脸的五官标记。原图与扩展图的头部宽度和位置存在差异，仍复用同一采样公式。脸型改变后部件不随真实骨相适配。
3. 头发与胡须是固定矩形适配。`GroomingLayer` 的目标位置按性别和发型指定，不按基础脸、发际线、下颌或嘴角调整；部分矩形改变源图宽高比。头发整层在衣服之后绘制，没有前发与后发分层；因此披发无法按身体部位正确遮挡。
4. 脖颈是拉伸补丁。`NeckUnderCollar` 从图集中取宽度约2%、高度8像素的一小块，拉伸成72×65的脖颈补面；所有服装共用头部260×260、躯干400宽和固定起点。没有逐套服装的领口与颈部接合数据。这会让颈部纹理、阴影和衣领衔接不自然。
5. 色彩处理不足。五官色差仅取一处脸颊颜色并限制在±0.10校正；肤色是全图乘色，无法分别处理皮肤、眉眼、嘴唇、阴影。独立光照和年龄纹理差异仍会保留。
6. 两条随机入口不一致。`CommandRules` 对队友随机结果重新统一年龄供体与发色；编辑器“随机组合”直接调用 `AppearanceRules.Randomize`，独立随机每个五官。玩家点随机或手动换基础脸后仍会出现不协调组合。选择基础脸不会自动同步已有的独立五官设置。
7. 图集边缘需重新验收。直接查看光头、扩展与头发源图能看到边缘杂色或孤立碎片，尤其头颈、领口和相邻素材区域。运行时还用 `ExcludeAtlasRegion` 硬编码剔除部分头发区域，说明素材裁切依赖局部补丁。透明度污染的精确像素范围尚未量化，不将所有彩色边缘都断言为最终屏幕可见。
8. 质量测试不足。`FacePixelsDiffer` 仅要求面部区域超过8个像素变化；其它测试检查索引、资源加载、着色器编译和保存读取。即使变得更难看也可能通过。已存在截图输出，但没有覆盖所有交叉组合的视觉验收标准。200次随机数据验证不等于200个人物通过美术验收。

## 修复次序

1. 先选定男女各一个标准头身模板，确定颅顶、眼线、鼻底、嘴线、下颌、颈根、肩线；同时验证半身图与名录裁切。
2. 制作符合模板的独立五官资源或经验证的局部形变方案，淘汰跨整脸图集按固定椭圆移植的实现。皮肤底图、五官、前后发、胡须、颈部、服装建立明确分层；不能只增加同类整脸图集。
3. 用部件元数据记录锚点、原始比例、兼容脸型、领口遮挡与允许的色彩区域，替代散落在代码里的矩形常量。
4. 统一编辑器和成员生成器的组合约束。换基础脸明确处理不兼容部件；随机角色与手工角色走相同渲染和校验路径。
5. 建立视觉验收矩阵：男女、所有基础脸、每种发型胡须与领口、肤色极值、年龄混搭、两种显示尺寸、预设与读档。逐张验收后再扩充资源。

优先解决脸颈接缝、头身比例和发际线，再恢复完整五官混搭。不能以隐藏五官选项或只调整预览缩放充当完成独立编辑。

## 责任与范围

上轮 v0.14 的随机成员接入、年龄协调和头像裁切有效，但没有重做上述合成架构。将功能测试通过表述为整体外观质量已解决，证据不足。本审查不认为用户操作或显示分辨率是这些根因。
