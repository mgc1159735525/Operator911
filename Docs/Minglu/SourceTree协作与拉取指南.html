拿到项目，开始开发

这份说明供第一次加入“明路·地下”的程序、美术和策划使用。SourceTree 管理本地 Git；GitHub 保存共享远程仓库。只有提交并成功推送，新内容才会出现在其他人的电脑上。

远程状态：等待仓库所有者完成 GitHub 登录。计划新建私有仓库 Operator911。尚无可核实的克隆地址；不要将本机 D 盘路径发给其他人作为远程地址。创建和首次推送成功后，此处更新实际地址。

1 · 新开发者第一次获取项目

  1. 安装 SourceTree 和 Unity Hub。安装时使用自己的账号；Git 作者姓名、邮箱也填写自己的信息。
  2. 将自己的 GitHub 用户名交给仓库管理员。管理员在私有仓库 Settings → Collaborators（组织仓库按团队授权）邀请；你接受后先用浏览器确认能访问仓库。不要共用管理员账号或令牌。
  3. 从本页远程信息或仓库绿色 Code 按钮复制 HTTPS 克隆地址。格式为 https://github.com/所有者/Operator911.git；“所有者”必须使用真实账号，不要照抄示例。
  4. 打开 SourceTree → 克隆 / Clone。源地址填远程 HTTPS 地址，目标路径选一个空文件夹，例如 D:\UnityProjects\Operator911，名称填 Operator911，点击克隆。已有同名项目时不要向其中再次克隆。
  5. 认证提示出现时使用自己的 GitHub 登录。SourceTree 的“工具 → 选项 → 身份验证”可配置 GitHub 账号；界面文字可能因语言版本不同。普通 GitHub 密码不能作为 Git HTTPS 密码；按客户端支持的 OAuth 或凭据管理器流程授权。
  6. 完成后确认左侧有本地 main、远程 origin/main，历史顶部提交与管理员交接记录一致，文件状态没有意外修改。

已经有本机项目的人：SourceTree → 添加 / Add → 工作副本路径选 D:\UnityProjects\Operator911。本机已存在这个书签，不要再次“创建仓库”。

2 · 第一次打开与运行

  1. 在 Unity Hub 安装项目指定编辑器 2022.3.62f3c1，以 ProjectSettings/ProjectVersion.txt 为准。不要擅自用更高版本打开并保存；若 Hub 不显示该版本，向负责人确认对应中国版安装来源与组件。
  2. Hub → 添加已有项目 → 选择包含 Assets、Packages、ProjectSettings 的根文件夹。首次导入需要联网下载包，并生成 Library，等待编译完成。
  3. 打开 Assets/Minglu/Scenes/MingluPrototype.unity，点击 Play，确认进入游戏主菜单。场景名字保留历史命名，当前首脑模式由 CityGameUI → DrawCommandGame → DrawDossierDesk 驱动。
  4. 从主菜单选择新手演练，检查地图、任务、人事与结束今夜操作。开发测试使用隔离进度，避免覆盖自己正在玩的真实存档。
  5. 美术校准器从 Unity 顶部 Minglu → 美术工具 → 人物部件校准器 打开，也可用 Ctrl+Shift+P。详细操作见校准器教程。
克隆到的是源码与素材，不含已打包游戏。Builds、Library、Logs、outputs 都不上传。新电脑没有 EXE 或历史截图是正常情况；项目导入成功也不等于构建与发布验收通过。

3 · 每天按这个顺序协作

  1. 开始前：保存并关闭 Unity 中正在编辑的场景；确认 SourceTree 文件状态干净。未完成的修改先提交到自己的分支，或用“贮藏 / Stash”（确认包含需要的未跟踪文件）保存。
  2. 同步主线：双击本地 main 切换，点击 Fetch，再 Pull，选择 origin 的 main。团队默认使用普通合并；不随意启用 rebase 或强制推送。
  3. 开分支：在最新 main 上点击“分支”，例如 feature/portrait-colour、fix/mission-return；Codex 自动创建的分支使用 codex/ 前缀。一个分支处理一个明确问题。
  4. 做改动：重新打开 Unity。改动前看制作看板与根目录 AGENTS.md；完成后运行相关检查、查看实际画面，并更新QA 记录。
  5. 提交：逐个看文件差异，暂存本次相关文件。填写可理解的提交说明，例如“修复长者嘴部肤色色块，保留唇色”。不要把个人配置、凭据、自动缓存一起提交。
  6. 推送：点 Push，选择 origin 和自己的同名分支，首次推送勾选追踪。确认成功；只点 Commit 不会上传。
  7. 合入主线：在 GitHub 为自己的分支创建 Pull Request，写清问题、改动、验证结果、剩余风险；负责人审核并合并。合并后切回 main 并 Pull；确认内容在远程 main 后再清理已合并分支。

确认上传完成：Fetch 后本地分支不再显示待推送提交，GitHub 上相应分支出现同一提交号。仅看 SourceTree 文件状态为空，不能证明已推送。

4 · 本项目的文件地图与资源规则

目录 / 文件用途与协作约定
Assets/Minglu/Runtime运行时代码；当前玩法以首脑模式入口为准，不要误改历史原型流程。
Assets/Minglu/EditorUnity 工具、配置编辑器、校准器、规则与渲染验证。
Assets/Minglu/Resources/Minglu/Art/Classic当前人物原画、部件贴图与 Portrait.shader；素材与对应 .meta 一起提交。
Assets/Minglu/Resources/Minglu/Configcommand_config.json：成员 / 任务；command_campaign.json：主线；strategy_config.json：地区；portrait-calibration.csv：人物位置 / 大小 / 间距。
ArtSource、Tools、Docs美术源文件、处理与交付工具、开发文档；一并纳入版本历史。
Packages、ProjectSettings包版本与工程设置；修改需说明原因。不要擅自升级 Unity 或依赖。
Library、Temp、Builds、Logs、outputs、UserSettings缓存、构建、证据或个人设置，由 .gitignore 排除。证据在各开发机重新生成或另外交接，源码仓库中的历史证据链接可能不存在。
  • 在 Unity 内移动、重命名资源，保留原 .meta GUID；删除素材时连同对应 .meta 一起提交。不要为已有资源重新生成 .meta。
  • 眼睛、眉毛独立；修改人物原画要复核脸型、肤色、年龄、部件边缘与缩略图。校准器“保存到项目”才更新共享 CSV，Library 草稿不会给同事同步。
  • 同一贴图、场景或人物校准表尽量同一时段只由一人编辑。CSV 合并以 sex/head/part/variant 组合键检查，避免重复行或误覆盖其他人的位置。
  • PNG 等二进制素材无法像代码逐行合并，冲突时联系原作者确认保留哪份。当前仓库未启用 Git LFS；2026-10-15 检查所有历史，最大单个 blob 约 11.9 MiB，无超过 100 MiB 文件。后续大素材先与负责人商量 LFS，不擅自改写共享历史。
  • 真实玩家存档位于 %USERPROFILE%\AppData\LocalLow\DefaultCompany\Operator911，不属于源码仓库；改项目显示名不能改变这条兼容路径。

5 · 出现冲突时怎么处理

  1. 先保留自己的工作：提交到个人分支或 Stash，再同步；不要为了让 Pull 成功直接“丢弃全部”。
  2. 拉取或合并出现冲突，先暂停 Unity，SourceTree 文件状态会列出冲突文件。代码 / JSON / CSV 打开比较工具逐段合并，移除冲突标记，再标记已解决。
  3. PNG、字体、复杂场景与 .meta 冲突联系作者；“使用我的 / 使用对方的”会舍弃另一侧内容，确认后才能点。无法判断时用中止合并恢复到合并前，保留个人提交等待处理。
  4. 解决后重新导入 Unity、编译、检查实际受影响流程，再提交合并并推送。不要靠“没有冲突标记”判断功能正常。

误提交但已推送：优先用“反向提交 / Revert”生成修正记录，或追加修复提交。共享 main 不执行强制 Push、hard reset 或历史重写。

6 · 验证、构建与交接

开发者每次至少检查本次改动的正常路径、取消返回及相邻流程。涉及资源或布局必须看实际渲染；涉及保存必须验证旧档、失败提示及重试。测试故障仅注入隔离路径。正式交付按 AGENTS.md 完整执行。

需要正式验证与 Windows 构建时，先关闭占用同一工程的 Unity，在项目根目录 PowerShell 运行（编辑器安装位置不同需调整）：

New-Item -ItemType Directory -Force Logs | Out-Null
$unity = 'C:\Program Files\Unity\Hub\Editor\2022.3.62f3c1\Editor\Unity.exe'
$build = Start-Process $unity -ArgumentList "-batchmode -nographics -projectPath `"$PWD`" -executeMethod Minglu.EditorTools.PresentationVerification.BatchDeliver -logFile `"$PWD\Logs\release-quality-build.log`"" -WindowStyle Hidden -Wait -PassThru
$build.ExitCode
Select-String -Path Logs/release-quality-build.log -Pattern 'MINGLU_BUILD_SUCCESS'

检查退出码、成功标记与错误内容，不能仅凭 EXE 存在判断构建成功。游戏输出为 Builds/MingluCity/MingluCity.exe；运行需要整个输出目录。UI 自动检查使用 --minglu-capture 的隔离存档，并按对应专项要求运行；构建成功不会自动生成所有 UI 与安装证据。

安装 Inno Setup 6 后，已有当前正式构建可运行：

powershell -NoProfile -ExecutionPolicy Bypass -File Tools/Installer/Build-Installer.ps1 -SkipGameBuild

安装包输出 Builds/Installer/MingluSetup.exe。本机固定安装目录 D:\Games\MingluCity。完整交付还需实际 UI 检查、安装后验证、文件与存档哈希核对，最后运行：

powershell -NoProfile -ExecutionPolicy Bypass -File Tools/Release/Review-Quality.ps1 -RequirePass

输出 outputs/release-current/quality-status.json。新克隆缺少历史 Logs / outputs 时门禁失败属于缺证据，不能复制别人的成功日志冒充本机通过。安装 / Unity 路径目前有本机约定，其他电脑需核对脚本中的路径。自动检查通过仍不等于商业发行合格。

7 · 常见问题速查

现象处理
Repository not found / 403确认已接受私有仓库邀请、地址正确、客户端登录的是获授权账号；不要立即新建另一个同名仓库。
GitHub 连接超时检查本机网络和已配置代理；浏览器与 Git 不一定共用代理。不要照搬别人的端口，不把账号或访问令牌写进 URL。
推送被拒绝 non-fast-forward先 Fetch 查看同事新增提交，保存自己的工作后 Pull / 合并、验证，再 Push；不要 Force Push。
同事看不到我修改确认文件已保存到磁盘、已暂存并 Commit、Push 成功，而且双方查看的是同一分支。
打开后大量文件变更检查 Unity 版本、换行与包升级。先看差异，别把全部自动变化一起提交。
找不到游戏 EXE / 截图链接打不开它们在被忽略的 Builds / outputs 中，需要自己构建或让负责人单独交接证据；Git 源码克隆不会下载这些内容。
修改校准没有同步在校准器保存到项目，确认 portrait-calibration.csv 有实际差异，再 Commit + Push；仅保存 Library 草稿无效。

交接前逐项确认

  • 新成员可访问私有仓库，使用自己的账号克隆成功。
  • Unity 版本正确，主场景可编译启动，校准器菜单可打开。
  • 能在个人分支提交并推送，在 GitHub 看到相同提交号。
  • 知道主线入口、素材 / .meta 规则、校准表保存位置和真实存档保护约定。
  • PR 记录实际检查范围、实图与未完成问题；未测项不写成已通过。
