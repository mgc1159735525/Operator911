# 配置与导表工具 v0.2

## 使用入口

工作簿：`outputs/minglu-v02/明路地下_游戏配置.xlsx`。

Unity菜单：`Minglu > 配置表工具`。

1. 在Excel中修改并保存。
2. 在工具窗口选择xlsx，点击“预览与校验”。
3. 校验通过后点击“重新读取并导入”。按钮会重新读取磁盘内容，避免预览后修改未被导入。
4. 在Unity中Play并新开局查看效果；进行中的对局和已有存档保持自己的规则。
5. 若要更新独立EXE，使用 `Minglu > 构建Windows试玩版`。已打包版本包含构建时的配置，编辑工作簿不会直接改变旧EXE。

也可选择包含六个同名CSV文件的目录。CSV为UTF-8，支持BOM、引号、逗号和单元格内换行。
从当前配置导出CSV可用于备份和版本比较；该操作不会反向修改xlsx。

## 工作表结构

| 表 | 主键 | 负责内容 |
|---|---|---|
| Settings | id | 回合、目标、AP、审讯、恢复与压力参数 |
| Agents | id | 人名、身份、小传、能力、上线、立绘列 |
| Districts | id | 六区域坐标、风险、难度、情报和成果奖励 |
| Actions | id | 五类行为的成本、需求和奖励 |
| Events | id | 指定回合出现的密报、两个选项及效果 |
| Assets | id | 城市与角色图集的Resources引用 |

第一行为英文程序字段，第二行为中文字段说明且第一格以#开头；数据从第三行开始。
CSV导出不包含说明行，导入同样支持。
程序按列名读取，可重排列，但不允许丢列、重复列或随意新增程序字段。
数值必须是确定值。Excel公式会被拒绝，避免缓存值过期；先粘贴为数值再导入。

## 验证与发布

验证字段类型、范围、重复ID、上下线外键与循环、地图坐标、五种行为ID、事件回合唯一性和至少一个免费选项、纹理资源存在性。
失败时报告表与字段/行位置，保留旧配置。

只有完整读取和校验成功，才写入临时文件并替换：
`Assets/Minglu/Resources/Minglu/Config/game_config.json`。
已有配置保留 `.bak`。运行时通过Resources加载，不依赖Excel、Node或办公软件。

当前限定2—8名成员、6区域、5固定行为、四列立绘索引0—3。新增行为或任意地图数量需要扩展代码，不能仅新增一行。
休整与断线不掷骰，Actions中的判定和奖励字段须为0；效果由Settings控制。
剧情事件在进入指定回合时触发，结局出现后不再触发后续事件。

## 存档与配置版本

v2文件名 `minglu-city-v2.json`，保留旧的 `minglu-prototype-v1.json`。
存档包含当局完整配置、角色、地区派遣、待处理事件、完成事件、日志和随机状态。
因此调表不会改变旧局的结果；如需体验新的平衡参数，开始新局。

## 开发入口

- `ConfigTableTools.cs`：xlsx/CSV解析、导出、预览窗口、发布。
- `GameConfig.cs`：字段模型、运行时加载及语义校验。
- `PrototypeRules.cs`：配置驱动的结算。
- `CityGameUI.cs`：布局、地图、派遣、弹窗、音效、截图及UI冒烟入口。
- `CityVerification.cs`：导表、地区、事件、快照和模拟回归检查。
- `Tools/Minglu/build_workbook.mjs`：生成初始模板和CSV；这是模板重建脚本，会覆盖交付的初始工作簿，不应用于保存日常调表修改。

命令行批处理：Unity的 `-executeMethod Minglu.EditorTools.ConfigTableTools.BatchImport` 导入默认工作簿；`Minglu.EditorTools.CityVerification.BatchDeliver` 导入、测试并构建Windows版本。

UI截图使用 `--minglu-capture <绝对png路径>`。该模式使用临时存档，点击真实Button监听器进行流程检查，不改写玩家存档。
