# 新手引导与首局体验设计

状态：设计稿，依据 v0.15 实际规则与界面制定，尚未接入游戏。时间目标与指标是待试玩验证的设计目标。

## 1. 核心体验

玩家应在首次结算后理解一句话：**我决定谁做什么，成员自行行动；我的工作是维持整个组织的运转。**

基本循环只有四步：看本夜目标 → 安排人员 → 推进一夜 → 根据结果调整。

“易上手”来自目标明确、操作可撤回、反馈可追踪；“难精通”来自同一批人无法同时满足情报、任务、生活和成长需求。不要通过隐藏规则、复杂点击或突然惩罚制造深度。

## 2. 当前开局的实际障碍

| 当前实现 | 首次游玩问题 | 设计调整 |
|---|---|---|
| 6人、3项任务、2条空链同时出现，默认提示先搭链 | 玩家尚未理解授权与结算，就要理解三岗位 | 第一夜仅突出1项任务；链条在首次结算后进入教学 |
| 左侧成员展示角色信息，能力详情在右侧 | 选谁缺少直接比较 | 任务选中后，名录显示相关能力、骰数、当前职责与冲突 |
| 推荐按骰数优先，机动成员仅作同骰数次序 | 可能推荐正在承担接头的人，打断链条 | 先分“可直接执行”与“会中断岗位”，给出推荐理由和代价 |
| 每次结算转到长日志 | 新玩家难以知道哪项决定造成了什么 | 结算摘要先展示结果、原因、下一步，日志可展开 |
| 换链条成员立即清空积压 | 正常人事轮替产生出乎意料的损失 | 引导上线前先修正交接规则；不能靠提示教玩家接受隐性惩罚 |
| 第4夜起随机事件可直接出现信任危机 | 尚未理解风险时就可能失去成员 | 首次事件固定为可恢复的生活请求；严重事件分阶段开放 |
| 20夜或8夜只按时长描述 | 新手可能以为8夜更容易 | 改名“标准行动·20夜”和“限时挑战·8夜”，首次默认标准 |

成员继续全随机，不恢复固定主角队伍。引导使用当前成员姓名、能力与外观生成文本。

## 3. 首局模式与保护规则

主菜单主按钮：**首次接任 · 带引导**。旁边提供“标准行动”和“限时挑战”，有经验玩家可直接进入。外观设置可随时进入，不强制作为开始游戏的前置步骤。

首次接任采用标准20夜，不在角色创建时要求理解流派、危机和高难度。高级开局参数折叠为可选项。

开局短文不超过两段：

> 你刚接管本地区的组织。成员各有工作与家庭，也有人长期潜伏在关键岗位。
>
> 上级希望你先完成一次人员安排，再恢复一条稳定的情报联系。你负责下达指示，具体行动由成员完成。

首局保护公开列在模式说明中：

- 前3次结算不发生叛离与大清查；之后仍需相应教学里程碑与预警条件满足才开放。
- 第一项任务不在讲解期间倒计时失效。开始尝试后给出至少3次执行机会；真实骰子照常判定，不暗改骰面。
- 人选匹配开局实际队伍：从四项能力中选存在至少4骰候选人的能力，要求1个成功；若极端种子无此人，使用队伍最高能力，不修改随机角色能力。
- 首项任务失败仍展示完整反馈并推进“学会授权”的教学，不把成功作为教程解锁条件。到期后提供同类替代任务，不能断掉唯一学习路径。
- 一夜内最多引入一个新机制；不同时弹升级、事件、上级来令和教学弹窗。
- 引导提示与首局保护分别记录。玩家可关闭提示，首局保护按原声明持续；不能通过反复开关提示重领补助。

**不承诺首局必赢。** 保护提供理解与补救机会，不保证每次行动成功，也不屏蔽真实成本。

## 4. 前30分钟体验节奏

以下夜数是目标节奏，实际由完成行为触发。玩家可以提前完成、返回查看或跳过提示；低概率失败不应迫使其重复教程台词。

| 节点与目标用时 | 玩家做什么 | 新学内容 | 关键反馈 | 下一步触发 |
|---|---|---|---|---|
| 接任，0—1分钟 | 阅读职责，进入任务指挥 | 自己是负责人，不是外勤 | 一个明确的“今晚先完成一次授权”目标 | 开始查看任务 |
| 第1夜，1—5分钟 | 比较两名候选人，授权一项基础任务，推进 | 能力→骰数→成功概率；授权不等于已经执行 | 骰面、实际消耗、任务结果；失败显示补救入口 | 完成一次真实结算并阅读摘要，不要求任务成功 |
| 第2夜，5—10分钟 | 依据能力安排内线、接头人、交通员，启用第一条链 | 岗位分工、一人一岗、长期运行 | 卡片连接成箭头；立即标出下一位将行动的人 | 一条有效链启用 |
| 第2—4夜，10—15分钟 | 推进并查看一份情报跨夜移动；可重试上一任务 | 情报产生不等于送达，接头不能跳过 | 情报卡从待接→中继→送达；每一步有时间与负责人 | 查看接头与外送的执行反馈；送达晚于目标夜数则继续并行学习 |
| 第4—5夜，15—20分钟 | 处理一次生活请求，安排休整及替班，或接受暂停一夜 | 成员是有生活的人；轮替和保留机动力量 | 预览“该成员今夜缺席→此岗位等待”，次夜反馈恢复 | 做出安排并看到影响 |
| 第5—6夜，20—25分钟 | 在上级任务与成员提议中选优先级，查看身份成长 | 不是所有任务都要做；表身份有长期价值 | 两张卡明确收益、期限、能力与身份门槛 | 自主完成一次取舍；无需两项都成功 |
| 第6—8夜，25—30分钟 | 收到一次可预见的清查压力，自己决定降速或继续 | 短期产出与风险、安全之间的取舍 | 先有预警，再有选择与实际后果 | 连续两次无逐步提示的结算后完成教学 |

引导结束不是胜利结算。随后第9—20夜按正常关卡继续，让玩家用已经理解的规则争取过关。

### 第一夜具体交互

第一张任务卡示例为“核实一份来报”，实际需求技能随队伍适配。卡片只突出：要做什么、需要哪项能力、1个成功即可、收益、期限。

选中任务后，候选人直接比较。例如要求1成功：2骰为75%，4骰为93.75%；文案是“更擅长，失败可能更低”，不能写“必定成功”。4—6为成功骰，保留现行真实概率公式。

右侧主按钮：“授权给［实际姓名］”。点击后变为“已安排，等待执行”，底部主按钮才突出“推进一夜”。推进前可以撤回或换人，不收取资源。

首次结算先显示任务结果，再显示消耗和原因：

> ［姓名］完成了核实。4枚骰子中有2枚成功，要求1枚。
> 体力−14、精神−6；成果与银两按该任务配置增加。
> 下一步：恢复情报联络，让消息持续送到上级。

失败分支不评价玩家“选错”：

> 本次没有掷出成功骰。这是概率失败，人员条件满足。
> 任务仍可重试。你可以让他再试一次，或换一位状态更好的人。

首次摘要明确区分“条件不足无法派遣”“已执行但骰子失败”“因为岗位冲突未执行”，不能统称失败。

### 第一条链具体交互

保留三岗位，但改成点击岗位后列出适配人选，而不是要求玩家记住先点名录再点岗位。每张候选卡显示此岗位用哪项能力、骰数、成功率与是否占用其它任务。

显示一组建议分工，玩家仍需确认。建议按不同成员组成的整体方案评估，不为每个岗位都推荐同一个最高能力角色。三个岗位不允许重复。

首次启用链条时发放一份公开说明的“接任时留下的待接情报”，放在待接状态，让接头人当夜就有工作；这是一次性开局资源，不是假装内线已经掷骰成功。新增内线仍按正常节奏产出。

接头成功后显示“消息已进入中继，交通员下一夜尝试外送”；失败显示“仍在待接，成员下夜自动重试，无需重新授权”。仅第一份消息播放可跳过的详细流转动画，后续使用简洁摘要。

链条旁常驻：下一环节、当前负责人、是否可行动、阻塞原因。不要只显示三个数量。

### 第一次生活事件

在链条启用且至少结算一次后，由教学调度器选择一名活动成员提出生活请求。两个有效选择都允许：为他安排替班，或明确接受链条暂停一夜。没有合格替班者时仍能完成教学。

不强制让玩家造成事故再教学，不为了教学偷偷把成员状态降到危险值。提示实际影响，但不强制付钱才放行。

### 第一次自主取舍

并排展示一项上级任务和一项成员提议，至少各有一名现有成员可以执行。不要用尚无人能达到的职业门槛充当首个选择。

上级任务明确给组织阶段带来的进展；成员提议明确带来的银两、成长机会或未来收益。若本局当前模板尚不能提供这些不同收益，需要新增对应模板与真实效果后再使用文案，不能只改描述。

允许玩家都接，但即时展示岗位与人员成本；不要硬锁为二选一。精通来自看懂机会成本。

## 5. 界面信息的递进

开始只突出任务指挥、一个当前目标和相关成员能力。链条、人事、地图、完整报告可通过“查看全部”访问；这是逐步突出重点，不是删除功能。

当前目标固定包含四项：**要做什么 / 为什么 / 完成条件 / 去安排**。每次只显示一个主目标，最多一个次要提醒。

优先级：待决事件 → 会导致本夜无法执行的阻塞 → 当前教学步骤 → 紧迫任务 → 可选成长。提示根据真实状态生成，不能安排已脱离组织的人，也不能引导点击禁用按钮。

所有禁用操作都提供原因和可行的下一步。例如“身份差1级；安排日常工作可增长经验”，并允许定位到人事页。

结算摘要最多三张卡：

1. 本夜结果：任务、消息送达和资源净变化。
2. 需要注意：岗位冲突、缺席、到期或成长，按严重程度选最多两项。
3. 下一步：一个可执行动作，或明确说明“安排有效，可以继续推进”。

摘要保留详细日志入口。空闲不是无效行动：当夜有人恢复体力、处理生活或获得身份经验，必须显示这些收益。

推进确认页列出**实际将执行什么**，不是只统计授权任务数量。默认不因“没有任务”阻止推进：链条、生活和身份成长本来就可以是本夜目标。

出现零收益的特殊空转时给非阻断提醒；玩家确认后仍可推进。所有真正非法的授权由规则层拦截，不能只靠教程屏蔽。

## 6. 难于精通：规则不增加，权衡逐渐增加

| 新手理解 | 熟练后的决策 | 界面必须给出的证据 |
|---|---|---|
| 擅长的人骰子更多 | 最强的人要留给链条瓶颈，还是高收益临时任务 | 比较成功率、目前岗位、换人后的吞吐影响 |
| 链条要三个人 | 单环节高概率不等于整条链高概率，积压会改变优先级 | 各环节概率与队列；综合估计需注明假设与时间窗口 |
| 休息会恢复 | 决定谁轮替、何时降速，为后续事件留余量 | 预计恢复、生活积压与身份经验变化 |
| 身份高能接新任务 | 培养稀缺职业会占用即时产出的人员 | 未来准入、所需经验及当前可放弃收益 |
| 多一条链能增加产出 | 两条链占满6人后，临时任务和生活事件没有替班余量 | 启用第二条链前显示剩余机动人数 |
| 清查时可以暂停 | 根据期限、消息积压、资金和压力决定何时冒险 | 明确预警、已知后果与未知概率，不隐藏规则 |

例如三个环节各使用4骰、各需1成功时，若各尝试一次且判定独立，全部成功的概率约82.4%，不是93.75%。实际跨夜重试、人员状态和队列会改变结果；不能把82.4%伪装成实时整链送达率。

第二条链在首次送达后进入重点提示，但不作为强制教学目标。介绍时直接说明“会占用另外3人，可能减少应急余量”，不把扩张包装成必然升级。

叛离放在玩家见过信任预警并经历过处理机会之后；清查先预警再落地。正常模式仍可有不可控事件，但要让玩家能从结果追溯到风险来源。

## 7. 引导状态与配置

建议新增 `OnboardingState`，与对局一起保存：`version / mode / stepId / completedFlags / currentGoalId / hintLevel / hintDismissed / starterPacketGranted / pendingLesson / lastFocusedEntityId`。

引导步骤至少包括：`review_task → authorize → inspect_result → build_route → inspect_handoff → inspect_delivery → manage_life → choose_priority → independent_turns → complete`。

这是有条件的状态图，不是固定逐夜脚本。`inspect_delivery` 未完成时可以先发生生活教学；以完成标记汇总，不要求线性阻塞。读档后依据真实任务、成员与队列重算目标，不强迫再次点历史按钮。

建议步骤配置字段：步骤ID、前置标记、触发条件、目标实体选择器、目标页、提示文案键、完成条件、失败分支、替代步骤、一次性发放标记、优先级。文本存配置，概率和授权合法性仍用现有规则系统，不复制第二套规则。

选择器按角色状态匹配，禁止写死成员ID和姓名。找不到合适人选时，转为休养/换任务分支。若成员失效，不能保留悬空高亮。

首次游玩标志在局外档案记录，具体引导进度在局内记录。完成后默认不自动重复，随时可以在指南里复习。跳过提示不删除当前任务、不清空队列、不改骰子。

## 8. 引导上线前必须完成的规则修正

1. **正常换岗保留消息。** 将消息归属链条节点；授权换岗在结算前提交，消息仍留在原节点。保持一人本夜一个地下行动，避免交接与任务双重执行。若要销毁消息，应提供单独的明确操作与确认，不能绑定普通人事替换。
2. **启用前进行人员冲突预览。** 展示同夜任务优先造成的岗位停顿。推荐器优先给出无冲突方案，允许玩家主动选择有代价的方案。
3. **结算输出结构化结果。** 新增任务/接头/外送/生活的结果记录与原因码，摘要和教程依据事件记录工作；不要解析中文日志判断教程是否完成。
4. **首次事件调度与随机事件共享队列。** 一夜最多一个待决教学事件；延后的普通事件不得到下一夜集中连弹。严重事件开放条件与首局模式写入存档。
5. **教学首项任务保障可执行。** 生成时验证真实职业、身份等级、能力和状态；到期与失败有替代路径，一次性初始情报防止重复领取。

## 9. 验收与试玩

自动验证：

- 同种子首局重现，随机成员不被教学硬改成固定队伍。
- 首次任务连续失败仍能学习链条；有补救入口，没有强制重开。
- 第一环失败、接头人缺席、交通员冲突均显示不同原因；重试规则与实际结算一致。
- 所有步骤存读档、关闭提示、重新进入均保持进度；初始消息只发一次。
- 正常替班不清空积压、不让消息同夜穿越多环、不让成员一夜完成两项地下工作。
- 主目标始终指向存在且可操作的实体；玩家偏离教程仍有恢复路径。
- 1280×720与1600×900下引导不能遮住目标控件，也不能把日志当成唯一反馈。

找5—8位没看过策划案的玩家进行首轮观察，不边看边口头教学。以下为目标而非已取得结果：

- 多数玩家5分钟内自主完成首次授权和结算。
- 首次结算后能回答“我控制什么”“谁实际执行”。
- 首次送达后能说出接头人与交通员的区别，以及为什么消息没有同夜送达。
- 15分钟内能根据成功率、岗位或状态说明一次选人理由，而非只点推荐。
- 引导结束前能主动安排一次休养/替班，或解释为何接受暂停。
- 长时间停顿先观察原因；不以快速点击次数代替理解程度。

试玩记录只需本地事件日志与人工记录；本方案不默认接入外部遥测服务。

## 10. 制作顺序

第一批：正常换岗保留消息、推荐冲突分组、结算摘要、当前目标面板。它们同时改善所有玩家体验，不依赖教程。

第二批：首次任务、第一条链、一次性待接消息、生活教学、状态保存与跳过。先做完整的前15分钟闭环。

第三批：成员提议与上级任务的真实差异、风险预警、教学退出、首局复盘和真人试玩调优。

首局复盘解释两三项最重要的因果，不只给输赢：哪些安排维持了送达、哪里因为岗位冲突或缺席中断、身份成长差多少；提供一个下局可以尝试的调整。重开使用新随机队伍，引导默认关闭，规则完全保留。
