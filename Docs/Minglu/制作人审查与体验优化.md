# 制作人审查与体验优化

本次沿着“进入新局 → 安排人员 → 执行任务与链条 → 处理事件 → 培养身份 → 结局复盘”检查首脑模式。优先修复操作与实际规则不一致、玩家看不懂等待原因、失败无法追溯等问题，不用增加面板数量来替代体验改善。

## 已落地的调整

| 范围 | 原问题 | 现在的行为 |
| --- | --- | --- |
| 首次体验 | 新局先进入地图，引导却要求先建链 | 新局进入传递链条，前三夜显示三步清单：建链、授权任务、推进与读报告 |
| 指挥交互 | 先在远处选中队员，点岗位就替换，容易误操作 | 点岗位打开候选弹窗，按该岗位能力排序，显示骰数、当前成功率和被占用原因；同线重复人选不可选 |
| 任务可读性 | 未授权卡也一直显示不能用的撤回按钮 | 仅已授权任务显示撤回；任务主要操作仍为查看、推荐、对比 |
| 目标反馈 | 只显示关卡要求，看不到完成多少 | 简报与概况显示送达、任务、身份等级的当前数量与门槛 |
| 链条节奏 | 第一条链第一夜不产出，看起来没有执行 | 显示本夜各岗位执行/周期等待/上游等待/任务占用；无流转也写入报告。保留三段跨夜规则与观察周期 |
| 人员状态 | 底部卡片只显示岗位，休假或疲劳不明显 | 优先显示被捕、离队、休假、生活优先、状态不足、家事积压，随后才显示任务或岗位 |
| 导航 | 已安排休养的人仍不断成为“前往处理”的目标 | 休养或休假已安排的成员不再被重复催办；夜前检查标明已安排休养，仍超捕获阈值则继续警告 |
| 报告 | 倒序混合多夜原始日志，找不到一次失败的原因 | 按夜分页，默认结果与原因，失败、阶段完成、暂停、逾期都保留；详细骰面与方案消耗可展开 |
| 经济反馈 | 维护不足会掉信任，但缺少明显解释 | 夜末报告银两、情报前后数量、维护支出；经费不足明确说明信任和可疑度影响 |
| 任务预算 | 成员休假、叛离或生活优先后，旧授权继续占用预算 | 即时撤回相关授权、释放银两与情报，记录撤回原因；结算前再清理失效授权 |
| 尾声节奏 | 最后一夜还能领需要两夜的任务；被捕后营救根本来不及 | 剩余夜数不足时阻止授权；最后一夜不创建联盟；倒数第二夜被捕使用单阶段紧急营救 |
| 任务生成 | 失联者的高级身份仍能解锁任务，满待办时虚报新任务 | 只用在岗成员判断身份准入；确实创建成功才报告新事项；终夜结算不再产生无机会执行的自主任务 |
| 城区画面 | 地图只显示待办总量，紧急事项不突出 | 标注待授权/已授权；今夜截止且未授权的城区用文字与红色同时提示 |
| 外观闭环 | 负责人外观可编辑但首脑主模式找不到展示入口 | 组织概况展示负责人半身像，可直接进入编辑，应用后返回原概况弹窗 |
| 外观微调 | 撤销五官或配色后跳回基础面容 | 撤销、重做保留当前分类；性别改变使胡须分类失效时才回到合法分类 |
| 结局 | 结束后只能返回菜单，不能检查失败原因 | 增加逐夜复盘入口，可查看全部判定并安全返回结局 |
| 保存反馈 | 自动保存把刚完成操作的提示覆盖成“已保存” | 后台保存保留操作结果，手动保存才显示通用保存确认 |

## 设计取舍

- 玩家仍负责授权、轮休、身份成长和链条配置；不增加接头微操。
- 首夜建立规则认知，前三夜提供轻量清单。观察不是每夜产出，接头和外送也不能在同夜跨过两环，预报说明等待的原因。
- 不把低成功率等同于不可玩：成功率大于零的可行尝试仍由玩家判断；只有明确不能完成的条件才阻止授权。
- 警告不仅提示“危险”，也告诉玩家已采取的措施和待解决的原因。
- 原有立绘校准和写实部件继续使用；本次画面优化集中于层次、状态和阅读路径，没有重新生成角色部件。
- 不修改旧存档结构；新增报告从现有日志生成。旧日志没有新的账目记录时不会凭空补写。

## 验证方式

- Unity 规则回归：地区经营 30 条、任务 23 条、组织 22 条；组织回归另跑 60 次完整对局。
- UI 用实际按钮射线命中测试，不直接调用按钮回调跳过遮挡检查。新增 `--producer-only` 检查岗位选择/取消/重复限制、夜报分页与失败摘要、负责人外观存档与撤销、结局复盘；沿用组织、经营、外观工作室回归。
- 固定输出 `Builds/MingluCity` 与 `Builds/Installer/MingluSetup.exe`，不新增一个版本一个包的交付目录。
