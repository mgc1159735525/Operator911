# 明路·地下：首个可玩原型 v0.1

状态：验证核心循环的灰盒，不是正式美术版本。2026-09-27。

## 范围与进入方式

在现有Unity 2022.3工程新增独立的 `Assets/Minglu`，不替换HeroDispatch的脚本、Main场景和资源。

Unity菜单 `Minglu > 打开八回合原型`，点击Play。
场景路径：`Assets/Minglu/Scenes/MingluPrototype.unity`。
默认危机教学开局；顶部按钮可切换到常规开局。重开不覆盖存档，结算会自动保存。

本轮交付：四名固定角色、八回合、侦察/破坏/营救/休整/断线、简化敌方搜捕、单线泄密、胜负、因果日志、手动与自动存档。

暂不实现：区域差异、捏脸、正式立绘、完整性格与恩怨、招募、设施、跨局成长、20回合内容、移动端。
地区和好友关系推迟到闭环验证之后，避免以缺乏实际效果的占位功能冒充完成。

## 已冻结的原型规则

这些是用于验证的明确取舍，不宣称原策划所有冲突已经解决。

| 项目 | 原型口径 |
|---|---|
| 背景 | 架空古代地下组织，本轮不使用电台、清朝纪年或晚清身份 |
| 回合 | 最多8回合；任何结算后成果达到24且仍有可行动成员即胜利 |
| 失败 | 无可行动成员优先判败；第8回合结算后成果不足也失败 |
| AP | 全组织每回合3点；每人最多一个行动；休整免费；不收身份维持税 |
| 情报 | 开局1份；破坏/营救各预留1份，失败也消耗；本轮侦察所得下轮才可派用 |
| 骰子 | d6，4/5/6成功；侦察需1成功，破坏/营救需2；暂不设大成功、大失败 |
| 能力 | 侦察取情报，破坏/营救取潜行；体力低于70减1骰，低于40减2骰；暴露至少50再减1，最低1骰 |
| 侦察 | 成功得2份情报、2成果；消耗20体力，暴露+10，失败另+15 |
| 破坏 | 成功得8成果、敌方压力+8；消耗20体力，暴露+20，失败另+15 |
| 营救 | 骰子成功立即释放目标，体力50、暴露25、审讯归零；本轮不额外行动或恢复；已泄露信息不撤回 |
| 休整 | 体力+25、暴露-15，有上下界；未安排成员默认休整 |
| 断线 | 执行者转移地址、脱离旧上线改为直接联系领导者；暴露-25；本轮不另休整 |
| 被捕 | 敌方阶段暴露至少70即被捕，下一回合才开始审讯 |
| 审讯 | 被捕且未获救者每轮+1；达到2向仍使用旧联络线的直接下线施加一次暴露+40；达到4永久失联 |
| 敌方 | 压力初始15，每轮+4；达到50后，对可行动成员暴露+5，再检查被捕 |
| 时序 | 预留情报扣除 → 断线 → 按名录顺序行动 → 旧囚犯审讯 → 敌方搜捕 → 胜负 → 下一回合 |

当前角色ID稳定为0—3，沈默联系顾青，陈砚联系林叔。没有跨线泄露。
断线使接头地点失效，不代表囚犯忘记下线真名；原型用当前有效联系表示可追踪路径。
常规开局全员可行动，危机教学明确预置沈默被捕；不在对局中强制随机绑走角色。

## 信息与反馈

灰盒暂显示体力、暴露、骰子数、实际骰面，用于理解规则和调试，不作为正式版最终的信息披露设计。
隐藏性格、模糊能力、概率提示需在可解释性验证后引入。
每次结果记录行动人、成功数与需求、奖励、泄密原因与目标。
随机算法状态随存档保存，不依赖Unity全局随机；同一安排读档后相同结果。

## 架构与存档

- `PrototypeRules.cs`：纯C#状态、派遣校验、随机数与回合结算。
- `MingluPrototype.cs`：独立IMGUI灰盒界面；不引用原游戏管理器。
- `PrototypeSave.cs`：Unity JSON序列化、基础验证、临时文件替换及备份。
- `PrototypeTools.cs`：场景入口、可批处理规则验证、独立Windows构建入口。

存档为 `Application.persistentDataPath/minglu-prototype-v1.json`，与原游戏存档不同名。
单槽存档，替换时保留 `.bak`；本版不提供多槽、旧版本迁移、任意损坏存档修复。
日志本身和当前回合派遣也存档。保存失败会提示，保留内存对局。

## 验收与下一轮

先用 `Minglu > 验证核心规则` 检查AP/情报预留、派遣撤销、审讯与营救时序、泄密隔离、重复结算、胜负和存读档一致性。

人工试玩：
1. 危机局选择沈默为营救目标，让林叔营救；观察不同随机结果的风险与成本。
2. 让顾青断线，放弃营救；检查第二次结算的泄密不再追踪到顾青。
3. 既不营救也不断线，观察泄密与永久失联记录。
4. 常规局交替侦察、破坏和休整，完成八回合或提前胜利。
5. 安排好行动后保存，结算，再读取重做，核对骰面与结果。

首轮收集：能否不讲解完成第一回合、能否解释失败、营救与断线是否都有价值、是否愿意重开。
模拟局的胜负比例只是固定策略的回归信号，不能当作真实玩家胜率或平衡证明。

下一轮顺序：人工试玩修正反馈 → 简化人物关系 → 三区域差异 → 补充招募与任务链 → 扩展20回合。
